🛒 Shopify 開発者情報

サブスクの支払い方法失効理由に「RETRY_DECLINED」を追加 — 決済代行側が再試行をブロックしたケースを識別、GraphQL Admin API 2027-01

shopify
🔗 Shopify Developer Changelog

GraphQL Admin API 2027-01 から、CustomerPaymentMethod.revokedReason に新しい値 RETRY_DECLINED が返るようになった。サブスクリプションの支払い方法が、決済代行業者によってそれ以上の再試行をブロックされたために失効した場合に使われる。旧バージョンでは従来どおり TOO_MANY_CONSECUTIVE_FAILURES が返る。customer_payment_methods/revoke Webhook のペイロードは変わらないため、Webhook 受信後に revokedReason を照会し、マーチャントや購入者に別の支払い方法が必要であることを案内するよう推奨されている。

アプリの network_access 設定を開発ストアでテスト可能に — 宣言漏れの外部ホストを事前に検出

shopify
🔗 Shopify Developer Changelog

shopify.app.toml の [network_access] で宣言したアプリの外部通信先を、開発ストア上でテストできるようになった。開発ストア作成時に機能プレビュー「network_access_testing」を有効にすると、宣言した通信先が正しいか、記載漏れのホストやサーバーがないかを確認できる。プレビューは警告を出すのみで通信をブロックはしない。IP 許可リスト必須化と並んで進むアプリのネットワーク制御強化に備え、本番適用前の確認手段として活用できる。

security
🔗 アイリスオーヤマ

アイリスオーヤマは11月5日の第2報で、公式通販サイト「アイリスプラザ」への不正アクセスにより、最大約770万人分の個人情報が漏えいした可能性があると発表した。報道によると、会員・元会員約580万人と非会員約190万人が対象で、氏名・住所・電話番号・メールアドレス・生年月日・パスワード（暗号化済み）などが含まれる可能性がある一方、クレジットカード情報は含まれないとしている。同サイトは10月29日から停止しており、個人情報保護委員会と警察にも届け出済み。現時点で悪用は確認されていない。

Amazon S3 Tables が Apache Hive テーブルから Iceberg へのマネージド移行に対応 — 移行中も元テーブルへの読み書きが可能

cloud
🔗 AWS News Blog

Amazon S3 Tables で、AWS Glue に登録された Hive テーブルを Apache Iceberg テーブルへ移行するマネージド機能が提供された。互換性レポートの生成、型変換、再圧縮、コンパクションを自動で行い、start・sync・complete の API で差分同期しながら移行できるため、切り替え時の短い停止だけで済む。課金はコピーしたデータ量のみで変換自体は無料。対応は同一アカウント・リージョン内の Parquet 形式のテーブルに限られ、東京を含む10リージョンで利用できる。
