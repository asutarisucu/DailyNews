🔗 ITdaily

Anthropic は11月23日、Zero Data Retention（ZDR）契約の企業向けに、悪用検知の仕組み「Enterprise Frontier Safeguards（EFS）」のパブリックベータを開始した。従来の単一リクエスト単位のチェックに加え、複数リクエストにまたがる不正利用を自動監視する。プロンプトと出力は顧客自身のクラウドストレージに保管され、Anthropic やクラウド事業者の社員はアクセスできず、学習にも使われない。Claude Platform、Amazon Bedrock、Google Cloud で利用でき、Microsoft Foundry への対応は今後予定されている。

【要更新】CISA が N-able Mail Assure と MONAI Label の脆弱性を KEV に追加 — 連邦機関の対応期限は11月26日

security
🔗 The Hacker News

CISA は11月23日、悪用が確認された脆弱性2件を KEV カタログに追加した。N-able Mail Assure / SpamExperts の CVE-2026-134624（CVSS 9.3）は LDAP 同期の接続確認処理における SSRF で、ビルド 20261121.1943 で修正済み。医療画像 AI 向け MONAI Label の CVE-2026-133968（CVSS 9.8）は認証不要のパストラバーサルで任意ファイル書き込みから RCE に至るもので、0.8.6 で修正された。後者は AI エージェントを使った攻撃で9月から悪用されていたと報じられている。Mail Assure 利用者は API・OAuth トークンのローテーションも推奨される。

【要対応】ASP.NET 向けライブラリ「Idunno.AntiCsrf」の RCE 脆弱性 CVE-2026-131914 が悪用中 — 修正版なし、モジュールの削除を

security
🔗 The Hacker News

Mandiant と watchTowr は、ASP.NET 用の CSRF 対策ライブラリ Idunno.AntiCsrf の安全でない逆シリアル化脆弱性 CVE-2026-131914（CVSS 9.3）が実際に悪用されていると警告した。トークンを鍵や署名検証なしの ObjectStateFormatter で復元するため、認証不要の POST 1回で IIS ワーカープロセス権限のコード実行が可能になる。対象は 0.9.1.0 と 0.9.1 Beta で、ライブラリはメンテナンスされておらず修正版は出ない。Web.config から AntiCsrfModule の登録を外し、DLL をデプロイ先から削除することが推奨される。

【要対応】Radware が侵害を公表 — 認証なしで外部から到達できた Cloud WAF 管理 API 経由で顧客のクラウドアクセスキーが流出

security
🔗 BleepingComputer

セキュリティ企業 Radware は、インターネットから認証なしで到達可能になっていた社内の Cloud WAF 管理 API を悪用され、一部顧客の連絡先とログエクスポート用認証情報（AWS S3 キー、Azure Blob キー / SAS トークン、SFTP 認証情報）が取得されたと公表した。最初の不正アクセスは11月19日で、約10時間後に検知された。WAF の通信検査や証明書、DDoS 対策サービスには影響はないとしている。対象顧客はログエクスポート用の認証情報をローテーションし、11月19日以降のストレージアクセスログを確認する必要がある。

AWS Network Firewall に「Automated Internet Firewall」がプレビューで登場 — VPC ごとの経路設定なしにインターネットゲートウェイで一元適用

cloud
🔗 AWS What's New

AWS は Network Firewall の新モード「Automated Internet Firewall」をパブリックプレビューで公開した。各 VPC にファイアウォールエンドポイントを配置してルートを編集する代わりに、Network Security Manager でルールを組織・OU・アカウント・VPC 単位で一元定義し、各 VPC のインターネットゲートウェイで適用する。新しい VPC やサブネットも自動で対象になり、適用前にモニターモードで確認できる。送信用 NAT 機能や AWS マネージドルールグループを含む既定ポリシーも備え、GovCloud と中国を除く全リージョンで利用可能。

dev
🔗 GitHub Changelog

GitHub は12月1日から1週間かけて、GitHub.com の通知の購読ルールを変更する。購読を解除したスレッドでは、コメントなどの通常のアクティビティで自動的に再購読されなくなる一方、メンションやアサインを受けた場合は従来どおり再購読される。チームメンションによる通知も、その時点のチーム所属に応じて届くようになる。利用者側の対応は不要で、GitHub Enterprise Server は対象外。
