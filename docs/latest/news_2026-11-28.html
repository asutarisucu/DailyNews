【要確認】Customer Account API の B2B アクセスを制限 — 顧客は所属する会社のデータと注文のみ参照可能に

shopify
🔗 Shopify 開発者 changelog

Shopify は Customer Account API の全バージョンで、B2B 顧客が読み取れる会社データと注文を、自分が所属する会社のものに限定した。スキーマ自体は変わらないが、一部フィールドが null や空リスト、少ない件数を返すようになり、連絡先の locations は本人以外だと空になる。税識別子や連絡先・ロール割り当てなども制限対象。マーチャントが会社から顧客を外すと、その会社の注文や下書き注文は参照できなくなる（個人の注文は引き続き表示）ため、注文履歴を表示するアプリは挙動の確認が必要。

Google の数学 AI「Cogentic」が人手を介さず論文6本を公開 — L[1/3] 時間の無条件素因数分解などを主張

ai
🔗 GIGAZINE

Google Research は11月25日、Gemini 4 上で動くマルチエージェントシステム「Cogentic」が生成した数学論文6本を GitHub で公開した。各論文には「最初のプロンプト以外に人間の関与はない」と注記され、数体ふるい法と同じ L[1/3] 時間クラスでの無条件の素因数分解、双行列ゲームの近似ナッシュ均衡、log-rank 予想の改善、Harary の辺再構成予想（密グラフ）などを扱う。オーケストレーターが証明方針を割り振り、検証エージェントが各ステップを攻撃する設計。査読前で、全証明の Lean 4 形式化は後日公開予定とされている。

【要確認】1Password が侵害を公表 — 社員の GitHub アカウント経由で一部顧客のアカウント情報とソースコードが流出

security
🔗 The Hacker News

1Password は、社員1人の企業用 GitHub アカウントが乗っ取られ、一部ユーザーのアカウント記録と非公開リポジトリのソースコードがコピーされたと公表した。調査開始は11月19日。流出した記録には氏名やメールアドレスのほか、アカウント ID、サインイン時刻、一部の招待・リカバリーリンクに含まれるトークンが含まれるとの報道もある。保管庫（Vault）の内容や暗号鍵、リカバリーキー、アプリには影響がないとしているが、CI/CD のインフラ用シークレットが露出した可能性があるため全面的な認証情報のローテーションを実施している。

SAP がサイバー攻撃を確認 — 社員のトークンを使い GitHub 上のソースコードが改ざんされたと Der Spiegel 報道

security
🔗 SecurityWeek

SAP は不審な活動を検知し、顧客とサービスを保護する措置を取ったと認めた。Der Spiegel は関係者の話として、攻撃者が SAP 社員の認証トークンを入手し、GitHub に保存されたソースコードをコピー・改ざんしたと報じている。SAP は顧客データへの不正アクセスの証拠はないとしており、改ざんされたコードが顧客向けソフトに組み込まれたとの報道もない。対策として GitHub へのアクセス制限、自動開発プロセスの一時停止、コード署名鍵の交換が行われたという。

【続報・要更新】Drupal のインストーラー修正に抜け穴、新たな CVE-2026-136716 が悪用中 — 11.4.14 / 11.3.23 / 10.6.23 で修正

security
🔗 SecurityWeek

Drupal は11月25日に SA-CORE-2026-019 を公開し、コアのインストーラーのアクセスバイパス CVE-2026-136716 が悪用されていると警告した。先に修正された CVE-2026-132165（Fail2Install）の対策で塞ぎ切れなかった問題で、インストールが不完全な状態のサイトでは未認証で再インストールを強制され、乗っ取りや RCE につながる。SA-CORE-2026-017 の後もインストーラーを外部公開していたサイトは侵害されている可能性がある。修正版への更新に加え、update.php の実行、install.php のブロック、ユーザー1の点検が推奨されている。

【要更新】NGINX の HTTP/2 RCE 脆弱性 CVE-2026-123007 に悪用報告 — シンガポール CSA が警告、F5 は「未確認」

security
🔗 シンガポール CSA

シンガポールのサイバーセキュリティ庁（CSA）は11月26日、NGINX の ngx_http_v2_module にある整数アンダーフロー CVE-2026-123007 が悪用されているとの報告があり、PoC も公開済みだと警告した。2015年の 1.9.5 から存在する欠陥で、未認証のリモートクライアントがキュー済みの応答データをキャンセルすることでメモリ破壊を起こし、条件次第でコード実行に至る。F5 は悪用報告を「技術的に未確認」としているが、HTTP/2 を有効にしたインターネット公開サーバーは NGINX 1.30.7 / 1.31.9、NGINX Plus 37.0.8.1 / 37.3.0.1 などへの更新が急務。

Azure Firewall のネットワークルールでワイルドカード FQDN が一般提供に — 3リージョンから、DNS プロキシが必須

cloud
🔗 Microsoft Learn

Azure Firewall のネットワークルールで「*.contoso.com」のようなワイルドカードドメインを指定できる機能が11月23日付で一般提供となった。サブドメインが頻繁に変わる宛先への TCP / UDP 通信を、個別に列挙せずにフィルタリングできる。利用には DNS プロキシの有効化と、クライアントがファイアウォールを DNS サーバーとして使う構成が必要。現時点の対応リージョンは West Central US、East Asia、UK South に限られ、HTTP/S と MSSQL には引き続きアプリケーションルールが推奨されている。
