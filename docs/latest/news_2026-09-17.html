🛒 Shopify 開発者情報

Shopify 2026-10 API リリース候補が公開 — Customer Account API で countryCode サポート追加・territoryCode 非推奨化、注文・税金・Storefront API に破壊的変更も

shopify
🔗 Shopify Developer Changelog

Shopify の 2026-10 API バージョンがリリース候補として公開され、10月1日の安定版リリースまで開発テストが可能になった。Customer Account API では顧客住所の countryCode フィールドが追加され、ISO 3166-1 alpha-2 に準拠した形式で住所の作成・更新・参照ができるようになる一方、既存の territoryCode は非推奨となる（互換性は維持）。また注文税金・下書き注文割引・メタフィールドフィルタ・税 ID ペイロード・カスタマーアカウントチェックアウトなど複数の破壊的変更が含まれており、早期テストと移行計画の策定が推奨される。

paymentInstrumentSendAddEmail ミューテーション新規追加 — サブスクリプション・注文・下書き注文で顧客への支払い方法追加リンクメールを API 経由で送信可能に

shopify
🔗 Shopify Developer Changelog

Shopify の Admin API に新たな paymentInstrumentSendAddEmail ミューテーションが追加された。このミューテーションを使うと、サブスクリプション・注文・下書き注文に紐付いた支払い方法を追加するためのリンクをメールで顧客に送信できる。これまではカスタマーポータル経由でのみ対応可能だった支払い方法の更新フローを、アプリやバックエンドから直接トリガーできるようになり、サブスクリプションや BtoB 受注フローの自動化が強化される。

🔒 セキュリティ

CISA KEV に CVE-2026-58704（Google Pixel モデムゼロデイ）を追加 — CVSS 8.0・認証不要・無インタラクションで特権昇格、限定的な標的型攻撃を確認

security
🔗 CISA

CISA が 9月16日に CVE-2026-58704（Google Pixel デバイスのモデムサブコンポーネントにおける不正認可）を既知悪用脆弱性（KEV）カタログに追加した。CVSS スコアは 8.0 で、セルラーモデムのコードに存在するロジックエラーによってパーミッションをバイパスできる。低複雑度かつユーザーの操作なしに悪用でき、標的がリンクをタップしたりアプリをインストールしたりしなくても侵害が成立するため特に危険。Google はセキュリティパッチレベル 2026-09-05 以降で修正済みであり、Pixel 6 以降の全機種が対象。端末の早急なアップデートを推奨する。

WSO2 API Manager の CVE-2026-5430（CVSS 9.8）が実環境で積極的に悪用中 — JWT アルゴリズム不正検証でアドミン権限取得、API Control Plane 等の利用組織に緊急対応を促す

security
🔗 The Hacker News

WSO2 API Manager および関連製品（API Control Plane・Traffic Manager・Universal Gateway）に存在する CVE-2026-5430 が、4月のパッチ公開後もなお実環境で積極的に悪用されていることが確認された。脆弱性は JWT トークンで未対応アルゴリズムを使用した場合の署名検証の不備であり、攻撃者が細工したトークンを送ることで API バックエンド・認証情報・登録済みアプリケーションシークレットに無断アクセスできる。CVSS スコアは 9.8（マルチテナント構成では 10.0 と評価）で、9月13日以降ハニーポットにアドミン権限埋め込みの JWT トークンが到達し始めているという。WSO2 製品を利用する組織は直ちにパッチを適用すること。

CISA が 7 件の悪用脆弱性を追加 — 攻撃者はリバースシェルと暗号通貨マイナーを展開、Starlette・LiteLLM の修正期限は 9月16日

security
🔗 The Hacker News

CISA が直近の KEV 更新で 7 件の脆弱性を追加し、攻撃者がリバースシェルや暗号通貨マイナーを展開していることを警告した。注目は Python Web フレームワーク Starlette と LLM ゲートウェイツール LiteLLM の脆弱性で、連邦機関向けの修正期限は 9月16日に設定されていた。AI・LLM インフラに使用されるライブラリが積極的な悪用ターゲットになっている点は注目で、Binding Operational Directive (BOD) 26-04 の下、利用組織は優先的なパッチ適用と侵害調査が求められる。

Amazon EBS ボリュームクローンがクロスアカウントコピーに対応 — KMS で再暗号化しながら別 AWS アカウントへ EBS ボリュームをコピー可能に

cloud
🔗 AWS Blog

AWS が Amazon EBS ボリュームクローン機能に、別 AWS アカウントへのクロスアカウントコピー機能を追加した。ボリュームを別アカウントにコピーする際、コピー先の AWS KMS キーで再暗号化しながら転送できるため、マルチアカウント環境での安全なボリューム共有が可能になる。これまで EBS スナップショットを経由した間接的な手順が必要だった運用が大幅に簡略化され、アカウント分離された環境でのデータ移行・バックアップ戦略の選択肢が広がる。災害復旧・テスト環境への本番ボリューム複製などのユースケースで恩恵が大きい。
