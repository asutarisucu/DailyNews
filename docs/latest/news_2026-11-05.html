🔒 セキュリティ

CISA が WordPress コアの脆弱性 CVE-2026-119977 を KEV に追加 — コア更新時の競合状態を悪用、連邦機関は11月6日までに対応

security
🔗 The Hacker News

CISA は、WordPress コアの自動更新処理に潜む競合状態（レースコンディション）の脆弱性 CVE-2026-119977（CVSS 8.1）を既知の悪用された脆弱性（KEV）カタログに追加した。更新時にインストーラーを含むファイルが予測可能な一時ディレクトリに展開されるため、その数秒間を狙った自動ポーリングでコード実行に至る恐れがある。影響は 4.7〜7.1.3 で、10月28日公開の 7.1.4（および各ブランチのセキュリティリリース）で修正済み。11月1日号で報じた攻撃の試みが、CISA により実際の悪用として確認された形だ。

サーバーセキュリティ製品 cPGuard の更新チャネルが乗っ取られバックドア配布 — 5.88.12〜5.88.19 が影響

security
🔗 The Hacker News

cPanel などのホスティングサーバー向けセキュリティスイート cPGuard の更新チャネルが11月2日に悪用され、Linux サーバーにバックドアと、パスワードハッシュなどを収集するスクリプトが配布された。影響を受けたのはバージョン 5.88.12〜5.88.19 で、5.88.26 以降への更新が推奨されている。スクリプトがコピーした認証情報はローテーションが必要とされ、セキュリティ製品自体がサプライチェーン攻撃の経路となった事例として注意が必要だ。

Siemens SIMATIC IoT2050 の最大深刻度の脆弱性 CVE-2026-58115 が悪用中 — 遠隔操作用バックドアを設置

security
🔗 The Hacker News

Siemens の産業用 IoT ゲートウェイ SIMATIC IoT2050 Advanced で、Node-RED の認証欠如により未認証の攻撃者が最高権限でコマンドを実行できる脆弱性 CVE-2026-58115（CVSS 10.0）が、遠隔操作用バックドアの設置に悪用されていると報じられた。脆弱性は8月に公表され、V4.3.4.1 以降で修正されている。OT 環境で未更新の機器を運用している場合は、更新に加えて Node-RED インターフェースの外部公開有無と侵害の痕跡を確認したい。

FBI、Binance から約64億ドルが流出した過去最大の暗号資産窃取を北朝鮮の TraderTraitor によるものと断定

security
🔗 The Hacker News

FBI は、暗号資産取引所 Binance のウォレットから60億ドル超が流出した事件について、北朝鮮のハッカー集団 TraderTraitor の犯行と結論づけた。当初は TRM Labs や Chainalysis などの民間分析企業が関与を指摘していたが、FBI は帰属を保留していた。流出の大半は約20分間に行われ、約30億ドル相当は凍結済み、Binance は損失を全額補償するとしている。侵入の起点は侵害されたノート PC とされ、2025年の Bybit 事件（約15億ドル）の4倍超の規模となった。

Google Cloud CLI 592.0.0 に破壊的変更 — Docker イメージで CLOUDSDK_PYTHON=python3 を指定すると gcloud などが失敗

cloud
🔗 Google Cloud CLI リリースノート

11月3日に公開された Google Cloud CLI 592.0.0 には破壊的変更が含まれる。リリースノートによると、Docker イメージで CLOUDSDK_PYTHON=python3 を設定している場合、gcloud・gsutil・bq の呼び出しが失敗するようになった。直近のバージョンではバンドル版 Python への移行が進んでおり、CI/CD などでこの環境変数を明示しているパイプラインは、更新前に設定の見直しが必要だ。

🔗 Microsoft Learn

cloud
🔗 WindowsForum

Microsoft の Azure Updates で、Azure Local（旧 Azure Stack HCI）上の VM を Azure Site Recovery で保護する機能が11月2日付で「Launched」となり、Azure Local がサポートされる全リージョンで一般提供された。オンプレミスの VM を Azure へレプリケートし、障害時にフェールオーバーできる。Windows Defender Application Control（WDAC）を有効にした環境もサポート対象となり、ハイブリッド構成の DR 設計がしやすくなる。

GitHub Desktop が短命の認証トークンに対応 — github.com 向けに段階展開、GHES は対象外

dev
🔗 GitHub Changelog

GitHub は11月2日、GitHub Desktop が有効期限の短い認証トークンを使うよう変更したと発表した。長期間有効なトークンが端末から窃取された場合の被害を抑える狙いで、github.com のアカウント向けに段階的に展開される。GitHub Enterprise Server は今回の展開に含まれない。開発端末を狙うインフォスティーラーやサプライチェーン攻撃が相次ぐなか、クライアント側の資格情報管理を強化する動きとなる。
