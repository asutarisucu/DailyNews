Anthropic が「Claude Ship」をベータ提供 — Claude が GitHub のプルリクエストをレビュー・修正し、ポリシーに沿って承認

ai
🔗 9to5Mac

Anthropic は、Claude が GitHub のプルリクエストをレビューし、修正をプッシュし、チームのポリシーが許す範囲で承認まで行う「Claude Ship」をベータで公開した。一般提供済みの Code Review に、修正を担う「PR Steward」と、リポジトリ内のポリシーファイルに基づいて自動承認する「Claude Approvals」（いずれもベータ）を組み合わせた構成。対象は GitHub を使う Team / Enterprise プランで、Claude Code の /ship で自分の変更をレビューに回せる。Claude はマージはできず、Anthropic はまず観察のみのモードで始めることを推奨している。

【要更新】Xen Orchestra の認証バイパス CVE-2026-133469 が悪用中 — CISA が KEV に追加、XCP-ng ホストの乗っ取りにつながる恐れ

security
🔗 BleepingComputer

仮想化管理ツール Vates Xen Orchestra に、細工した REST API の Cookie で未認証のまま管理者権限を得られる重大な欠陥（VSA-2026-062 / CVE-2026-133469）があり、攻撃者による悪用が確認された。管理下のプールでコードを実行し、XCP-ng ホストの root 権限を奪われる可能性がある。Vates は攻撃元 IP などの侵害指標を公開し、修正版（xo-server 5.211.2 / 5.213.1）への更新を呼びかけている。CISA は11月25日に KEV へ追加し、連邦機関の対応期限を11月28日とした。

security
🔗 Infosecurity Today

GeoServer は11月23日に5件の脆弱性を公表し、匿名の WFS アクセスから管理者セッションの偽造、OS コマンド実行まで連鎖できると説明した。うち CVE-2026-120705 と CVE-2026-129243 について、watchTowr はハニーポットで実際の悪用を観測したとしている。ハードコードされた署名鍵の問題（CVE-2026-129245）も含まれる。修正版は 3.0.2、2.28.6、2.27.7 で、すぐに更新できない場合は匿名ユーザーの WFS を制限するなどの緩和策が示されている。

AWS IAM の「信頼できる ID の伝播」が IAM フェデレーションと IAM Roles Anywhere に対応 — ロールの背後の人やワークロードを監査可能に

cloud
🔗 AWS What's New

AWS は11月25日、ロールセッションに元の利用者やワークロードの ID 情報を付与する「信頼できる ID の伝播（TIP）」を、SAML / OIDC による IAM フェデレーションと X.509 証明書を使う IAM Roles Anywhere に拡大した。ID 情報はロールの連鎖や下流のサービス呼び出しにも引き継がれ、IAM ポリシーの条件や CloudTrail で使える。IAM Identity Center での設定も簡素化された。全商用リージョン、GovCloud（US）、欧州ソブリンクラウドで利用できる。

Amazon RDS for SQL Server のインスタンスあたりデータベース上限が100から500に

cloud
🔗 AWS What's New

Amazon RDS for SQL Server で、1インスタンスに作成できるデータベース数の上限が100から500に引き上げられた。対象は 4 vCPU 以上（xlarge 以上、バースト可能クラスを除く）のインスタンスで、Single-AZ の各エディションと、Always On 可用性グループを使う Multi-AZ の Enterprise 系および Web エディションが含まれる。データベースごとに3つのワーカースレッドが必要なため、インスタンスの構成によっては500に届かない場合がある。

Vercel の AI Gateway に「Audited ZDR」— プロンプト非保持を第三者監査で証明したプロバイダーだけに振り分け

dev
🔗 The New Stack

Vercel は AI Gateway に、ゼロデータ保持（ZDR）を独立したセキュリティ企業の監査で確認し、結果を公開したプロバイダーにだけ付与する「Audited ZDR」ラベルを導入した。監査では ZDR 指定のリクエストが非 ZDR のエンドポイントにフェイルオーバーしないことや、顧客データで学習しないことも確認する。最初の対象は Baseten、Modal、Wafer で、監査報告は12月上旬に公開される見込み。OpenRouter 経由のプロバイダーで ZDR 指定のプロンプトが流出した問題を受けた動きで、チーム全体で監査済みプロバイダーにのみルーティングする設定も用意される。
